# Igrolit

Десктопный лаунчер: собирает игры из Steam, Epic Games, GOG и вручную добавленные в одном окне, показывает наигранное время из локальных данных Steam, хранит свои серверы и профиль.

Стек: Rust (Tauri 1.5), Svelte + TypeScript, Node.js-сервер на WebSocket.

Подпись Windows-сборок запрошена через SignPath Foundation — бесплатную программу для open-source проектов. До одобрения заявки сборки **не подписаны**, поэтому SmartScreen может показать предупреждение при первом запуске.

## Возможности

- Библиотека из нескольких платформ, поиск, сортировка, избранное, режим списка и сетки
- Превью игры с широким артом и статистикой Steam (`Playtime`, `Playtime2wks`, `LastPlayed`)
- Свои серверы с мониторингом статуса и числа игроков, каталог с закреплёнными слотами
- Профиль, друзья, чат, новости, поддержка, сохранения
- Аккаунт с 2FA, роли и админ-панель
- Автообновление и режим «Технические работы» при недоступном сервере

## Требования

- Windows 10/11 x64
- Node.js 20+
- Rust stable (MSVC toolchain)
- WebView2 Runtime (есть в Windows 11, в Windows 10 — обычно уже установлен)


## Сборка

```bash
npm run build:dev      # канал dev: доступны инструменты разработчика
npm run build:release  # канал release
npx tauri build        # установщики NSIS и MSI в src-tauri/target/release/bundle
```

## Тесты

```bash
npm run test:server                          # smoke-тесты HTTP и WebSocket API сервера
cargo test --manifest-path src-tauri/Cargo.toml   # юнит-тесты Rust
```

Smoke-тесты требуют запущенного сервера на `127.0.0.1:8787`.

## Сервер

```bash
PORT=8787 \
DATA_FILE=/path/to/data.json \
ADMIN_NAMES=admin1 \
node online-server/server.js
```

Эндпоинты: `/health`, `/status` (состояние, в том числе флаг техработ), `/app/latest`, `/app/file/<имя>`, `/app/publish` (только администратор).

## Обновления и подпись

Обновления раздаёт сервер: `/app/latest` отдаёт манифест с версией, SHA-256 и подписью Ed25519, клиент проверяет подпись перед подменой exe.

- Публичный ключ вшит в клиент: `src-tauri/update.pub`
- Закрытый ключ **не входит в репозиторий**: `update-signing.key` лежит рядом с инструментом публикации и добавлен в `.gitignore`
- Потеря закрытого ключа означает, что новые релизы клиенты не примут

Публикация:

```bash
# в приложении разработки: меню «Выкатить обновление»
# либо вручную: положить update-signing.key рядом с exe и выполнить публикацию
```

## Подпись кода (Windows)

Бесплатный вариант — SignPath Foundation: подписывают open-source проекты через собственный HSM, токен не нужен. Условия: публичный репозиторий и OSI-лицензия (этот проект — MIT).

Альтернативы: Azure Artifact Signing (~$9.99/мес), Certum Open Source (~$50/год).

Локальная подпись готового билда:

```powershell
$env:CODESIGN_PFX = 'C:\path\cert.pfx'
$env:CODESIGN_PASS = 'пароль'
npm run sign
```

Скрипт `scripts/sign.ps1` сам находит `signtool.exe`, подписывает exe, установщик NSIS и MSI, ставит метку времени.

## Безопасность

- Пароли хранятся в виде scrypt-хешей, сессии — токенами с ограничением по времени
- Критичные действия попадают в `audit.log`
- Обновления проверяются по SHA-256 и Ed25519-подписи
- Телеметрия по умолчанию выключена
